# 大尾巴闪念 PC 版——产品总览 PRD

> 文档版本：v0.5.1
> 日期：2026-08-12  
> 状态：已实现，候选验收版（Edge 和真实 Vault 已通过）

## 1. 产品背景

大尾巴闪念 Android 版已经可以把手机端闪念同步到 Obsidian。PC 端仍存在“复制内容后，需要切换到 Obsidian、打开笔记、找到正确位置再粘贴”的操作摩擦。

PC 版通过 AutoHotkey v2 提供三个系统级快捷键：保存普通闪念、保存待办、新建独立笔记。若内容来自网页，保存时同时记录来源网址。

## 2. 产品目标

### 2.1 核心目标

用户在浏览器、微信、Word、PDF 阅读器等 Windows 软件中复制内容后，通过一次快捷键完成保存；只有“新建笔记”需要弹出一个小窗口确认标题和正文。

### 2.2 成功标准

- 普通闪念和待办均为“复制—按键—保存”两步，不切换到 Obsidian。
- 新建笔记快捷键打开简洁窗口，剪贴板正文和网页来源自动带入。
- 三组全局快捷键可在 UI 中单独启用、关闭和修改并立即生效。
- 网页来源能够自动识别时，写入可点击的原始网址。
- 新内容与 Android 端使用同一目标笔记、锚点和主要 Markdown 结构。
- Obsidian 打开或关闭时均能保存。
- 任何失败都不破坏原笔记、不清空剪贴板。

## 6. 功能需求

### 6.1 FR-01 后台运行与快捷键

1. 脚本使用 AutoHotkey v2 运行。
2. 启动后只注册处于启用状态的 Windows 全局快捷键；首次默认注册普通闪念和新建笔记两组。
3. 快捷键修改后，点击“保存并应用”立即重新注册，无需重启。
4. 若已启用的快捷键为空、互相重复或被其他程序占用，显示错误并保留上一组有效快捷键；关闭项不参与注册和冲突校验。
5. 托盘菜单可以暂停和恢复全部快捷键。

### 6.2 FR-02 保存普通闪念

触发 `Ctrl + Alt + S` 后：

1. 优先识别剪贴板中的单张图片文件路径或 Windows 原始位图；否则读取纯文本。
2. 没有可保存文字或图片时不写入，并提示原因。
3. 去除首尾空白和行尾多余空格；单换行转为 Markdown 硬换行，一个或多个空行统一保留为一个段落间隔。
4. 获取可用的网页来源网址。
5. 生成普通闪念块；有可靠网页网址时增加“来自`域名`网页的剪藏。”。
6. 插入目标笔记锚点正下方。
7. 成功后显示约 2 秒的托盘提示，不抢焦点。

输出示例：

````md
**大尾巴闪念-202608121530**
来自example.com网页的剪藏。 #闪念

```markdown
第一段第一行
第一段第二行

第二段
```
记录日期:: 2026-08-12 15:30
来源网址:: https://example.com/article
备注::
^flash-20260812-153000-pc
````

未检测到网址时省略 `来源网址::` 整行。

### 6.3 FR-03 保存待办

触发 `Ctrl + Alt + T` 后，沿用普通闪念流程，但生成 Obsidian Tasks 兼容任务：

```md
**大尾巴闪念-202608121531**
- [ ] 整理这篇文章的要点 #闪念 #待办
  记录日期:: 2026-08-12 15:31
  任务ID:: pc-20260812153100-a1b2
  截止日期::
  提醒时间::
  来源网址:: https://example.com/article
  备注::
  ^flash-20260812-153100-pc
```

规则：

- `任务ID` 使用时间戳和四位随机后缀，保证稳定且尽量唯一。
- `截止日期`、`提醒时间` 在 v0.2.0 中保留空字段，不自动推断。
- 没有网页来源时省略 `来源网址::`。
- 创建后保持未完成状态，不自动发送提醒。

### 6.4 FR-04 新建独立笔记

触发 `Ctrl + Alt + N` 后打开“新建 Obsidian 笔记”窗口，而不是立即落盘。

窗口字段：

- 标题：必填；默认取剪贴板第一行，移除 Windows 文件名非法字符并截取前 40 个字符。
- 正文：自动填入完整剪贴板纯文本，保留换行，可编辑。
- 来源网址：自动识别，可编辑或清空。
- 保存目录：默认使用主设置中的目录，可为本次另选目录。
- 按钮：“创建笔记”“取消”。

创建规则：

1. 标题为空时禁止创建。
2. 正文允许为空，以支持只建标题笔记。
3. 文件名使用清理后的标题并追加 `.md`。
4. 同名文件已存在时，不覆盖，自动追加 `-yyyyMMdd-HHmmss`。
5. 保存目录必须位于 `C:\OBS\Damon` 内；不允许通过 `..` 跳出 Vault。
6. 目录不存在时不自动创建，提示用户回到设置选择有效目录。
7. 创建成功后可通过提示中的“打开”动作或托盘菜单在 Obsidian 中打开。
8. “在闪念笔记中插入链接”默认开启；创建成功后使用 Vault 相对路径生成 `[[路径|笔记名]]` 并安全插入闪念锚点下方。
9. 独立笔记已创建但回链失败时保留新笔记，明确提示部分成功及实际路径，不误报为创建失败或全部成功。

新笔记格式：

```md
---
创建日期: 2026-08-12 15:32
来源网址: "https://example.com/article"
tags:
  - 闪念
---

# 用户确认后的标题

剪贴板中的完整正文，保留原始换行。
```

没有网页来源时不生成 `来源网址` 属性。

### 6.4.1 FR-04A 内容格式模式

用户在设置界面从三种互斥模式中选择一种，保存后对普通闪念、待办和新建笔记立即生效：

1. `smart_markdown`：若剪贴板包含 CF_HTML，提取 `StartFragment/EndFragment` 区间，保留段落、换行和列表，将 `<strong>/<b>` 以及行内 `font-weight:bold/600–900` 转为 `**...**`，将 `<em>/<i>` 转为 `*...*`；无 HTML 时回退到纯文本段落。
2. `code_block`：当前默认。先按智能 Markdown 规则识别网页加粗，再将 Markdown 源码包装为语言标记为 `markdown` 的围栏代码块。普通闪念的标签、围栏、正文和元数据全部顶格，避免 Obsidian 软换行不继承列表缩进；待办代码块继续嵌套在 `- [ ]` 下。若正文已包含三个或更多连续反引号，外层围栏自动使用更长的反引号序列。
3. `plain_text`：只保留纯文本换行和段落，不解析 HTML 格式。

围栏代码块中的 `**加粗**` 仅显示 Markdown 源码，不会渲染成粗体；UI 必须明确提示该边界。

### 6.4.2 FR-04B 图片剪藏

1. 支持 `.png/.jpg/.jpeg/.gif/.bmp/.webp` 单张图片文件路径，以及 Windows 剪贴板 `CF_BITMAP` 原始位图。
2. 保存时读取 Vault `.obsidian/app.json` 的 `attachmentFolderPath`；当前 Vault 为 `assets`，缺项时也回退到 `assets`。
3. 外部图片必须立即复制进附件目录并生成唯一文件名；原始位图使用 Windows GDI+ 编码为 PNG。
4. Markdown 使用 Vault 相对 Obsidian 嵌入语法 `![[assets/图片文件名.png|300]]`，统一将 Obsidian 默认显示宽度限制为 300 像素，不受正文 `code_block` 模式影响；该参数不得缩放或改写原始图片文件。
5. 普通闪念图片顶格嵌入；图片待办嵌套于同一个 `- [ ]` 任务；新建笔记窗口以图片嵌入作为正文预填值。
6. 保存失败或取消新建笔记时，只删除本次新建且尚未被笔记引用的附件；Vault 内已有图片直接复用且不得删除。

### 6.5 FR-05 网页来源网址识别

网址识别采用三级策略，不安装浏览器扩展：

#### 一级：剪贴板 SourceURL

1. 保存触发时先通过 `ClipboardAll()` 快照完整剪贴板。
2. 读取 Windows 剪贴板注册格式 `HTML Format`。
3. 从 CF_HTML 头部解析 `SourceURL:`。
4. 只接受 `http://` 或 `https://`。

这是首选方式，因为它记录的是复制内容真正来源的网页，即使复制后切换了窗口，也不会误用当前窗口网址。

#### 二级：活动浏览器 UI Automation

只有同时满足以下条件才读取活动浏览器：

- 一级没有取得 `SourceURL`。
- “无法从剪贴板取得时，从当前浏览器补取网址”已开启。
- 热键触发时当前活动窗口属于 Chrome、Edge 或 Firefox。

程序优先通过 Windows UI Automation/MSAA 读取浏览器地址栏控件的值。该方式不发送按键、不改变焦点、不修改剪贴板。读取后仍需校验 `http://` 或 `https://`，并过滤浏览器内部页面。

#### 三级：地址栏复制兜底

只有二级 UI Automation 失败、当前窗口仍为受支持浏览器时，才执行最后兜底：

1. 保存完整剪贴板快照和当前活动窗口。
2. 向浏览器发送“聚焦地址栏、复制网址”。
3. 最多等待 800 毫秒获得新剪贴板内容。
4. 校验为 `http://` 或 `https://`。
5. 恢复触发前的完整剪贴板内容。
6. 焦点仍留在原浏览器窗口，不启动、不切换到 Obsidian。

边界：

- 若用户复制后已经切换到非浏览器窗口，而剪贴板又没有 `SourceURL`，则不附加网址，避免错误归因。
- 浏览器内部页面、扩展页、`file://`、`about:`、`chrome:`、`edge:` 不作为网页来源写入。
- UI Automation 和地址栏兜底均失败时，不影响正文保存，只在日志记录 `source_url_unavailable`，不弹错误窗口。
- 地址栏回退完成后必须恢复原剪贴板；恢复失败时取消本次写入并提示，避免污染用户剪贴板。

### 6.6 FR-06 设置主界面

主界面使用 AutoHotkey v2 `Gui` 实现，保持单窗口、少字段。

界面分区：

1. 运行状态：脚本版本、AutoHotkey 版本、快捷键启用/暂停状态。
2. 写入位置：Vault、闪念目标笔记、新建笔记默认目录均为只读字段，只能通过各自“选择”按钮更新。
3. 插入锚点：只读字段，只能通过“修改”按钮打开独立输入框更新。
4. 快捷键：普通闪念、待办、新建笔记各有启用开关和输入项；默认开、关、开。
5. 网页来源：自动附加来源、允许从当前浏览器补取网址两个开关。
6. 启动：开机自启开关，首次默认关闭。
7. 新建笔记回链：默认开启的“在闪念笔记中插入可点击链接”开关。
8. 操作按钮：“保存并应用”“测试配置”“使用说明”“隐藏到托盘”“打开笔记”“退出”。

“测试配置”只检查：

- AutoHotkey v2 版本满足要求。
- 目标文件存在，锚点非空且在目标文件中恰好出现一次。
- 新建笔记目录存在且位于 Vault 内。
- 已启用的快捷键合法、不重复并可注册。
- 目标文件可读写。

测试不向真实笔记写入内容。

### 6.7 FR-07 托盘菜单

托盘菜单提供：

- 打开设置。
- 使用说明。
- 暂停/恢复快捷键。
- 打开闪念目标笔记。
- 打开新建笔记目录。
- 退出。

点击主窗口关闭按钮仅隐藏到托盘；只有“退出”才结束脚本。

### 6.8 FR-08 配置

使用 AutoHotkey 原生支持的 `config.ini`，避免引入 JSON 库。

```ini
[Paths]
Vault=C:\OBS\Damon
FlashNote=C:\OBS\Damon\【MOC】闪念-随手记.md
NewNoteFolder=C:\OBS\Damon\01-看板-日记-杂项

[Write]
Anchor=<!-- DABAWEI_FLASHNOTE_INBOX -->

[Hotkeys]
Normal=^!s
Todo=^!t
NewNote=^!n
NormalEnabled=1
TodoEnabled=0
NewNoteEnabled=1

[NewNote]
LinkInFlashNote=1

[SourceUrl]
Enabled=1
BrowserFallback=1
AddressBarCopyFallback=1

[Content]
Format=code_block

[Startup]
StartWithWindows=0
```

配置文件不记录剪贴板正文、网页内容、账号、密码或 WebDAV 凭据。

## 7. 安全写入设计

### 7.1 闪念目标笔记

1. 文件不存在时禁止创建第二份同名笔记。
2. 配置锚点为空、不存在或出现多次时禁止写入。
3. 读取后记录文件大小、修改时间和内容哈希。
4. 在内存中构造新内容，并写入目标目录下的临时文件。
5. 替换前再次检查目标文件是否变化。
6. 发生并发变化时重新读取并重试一次；仍冲突则取消并提示。
7. 使用 Windows 同卷替换能力完成替换，失败时保留原文件。
8. 重新读取锚点附近内容，确认本次唯一 ID 存在。
9. 保持目标文件原有 UTF-8 无 BOM 和 LF 换行。

### 7.2 新建笔记

- 仅允许写入配置的 Vault 根目录以内。
- 清理文件名非法字符和尾部空格、句点。
- 避免 Windows 保留文件名，如 `CON`、`PRN`、`AUX`、`NUL`。
- 同名文件绝不覆盖。
- 写入失败时删除本次产生的不完整临时文件。

### 7.3 剪贴板保护

- 任何操作都不主动清空用户剪贴板。
- 地址栏回退必须使用 `ClipboardAll()` 保存并恢复文本、HTML、图片等全部格式。
- 日志不得记录剪贴板正文和完整网页网址；网址只记录“有/无”和获取方式。

## 8. 反馈与日志

成功提示：

- `普通闪念已保存`
- `待办已保存`
- `笔记已创建：文件名.md`

失败提示示例：

- `剪贴板没有可保存的文字`
- `找不到闪念目标笔记`
- `闪念锚点缺失或重复，未写入`
- `目标笔记刚刚发生变化，请再试一次`
- `新建笔记目录无效`
- `快捷键被其他程序占用`

日志保存到项目目录 `logs/flashnote-pc.log`，仅记录时间、动作类型、成功/失败、错误代码、是否取得来源网址及获取方式。日志最多保留最近 7 天或 1 MB，超过后轮换；不记录正文。

## 9. 非功能要求

- 仅支持 Windows 10/11。
- 明确要求 AutoHotkey v2，不兼容 AutoHotkey v1。
- 后台空闲时不持续轮询剪贴板，只在快捷键触发时读取。
- 普通闪念和待办从按键到反馈，正常情况下不超过 2 秒。
- UI 使用系统原生控件，不引入图片、WebView 或第三方 UI 库。
- 中文路径、中文正文、Emoji、网址参数不得乱码。

## 10. 验收标准

### 10.1 普通闪念

- 单行、多行、中文、英文、Emoji、网址参数均可保存。
- 复制单张图片文件或原始位图时，图片进入 Vault 附件目录，正文使用 Obsidian `![[...]]` 嵌入，不出现外部临时路径。
- 新记录位于唯一锚点正下方，原有内容完整。
- 单换行渲染为换行，空行渲染为段落间距，不再转换为 ` / `。
- 有来源网址时生成 `来源网址::`，没有时不生成空字段。

### 10.2 待办

- 生成 `- [ ]` 任务及 `#闪念 #待办`。
- 任务 ID 和块 ID 唯一。
- Obsidian Tasks 能识别为未完成任务。
- 来源网址规则与普通闪念一致。

### 10.3 新建笔记

- 快捷键打开小窗口，标题、正文、来源网址正确预填。
- 用户修改后按确认值创建 Markdown。
- 同名文件不覆盖。
- 不能写出 Vault。
- 创建成功后 Obsidian 能识别新笔记。

### 10.4 网页来源

至少覆盖以下场景：

1. Chrome 网页选择文字后复制，取得 CF_HTML `SourceURL`。
2. Edge 网页复制纯文本、无 `SourceURL` 时，通过 UI Automation 取得网址。
3. Firefox 网页复制并保存。
4. 复制后切换到 Word，仍优先使用剪贴板中的真实 `SourceURL`。
5. 从 Word、微信复制普通文本，不添加网址。
6. 当前浏览器页面为 `chrome:`、`edge:`、`about:` 或本地文件，不添加网址。
7. UI Automation 失败时允许地址栏复制兜底，且剪贴板文本和其他格式完整恢复。

### 10.5 异常与并发

- 空剪贴板不写入。
- 目标文件缺失、锚点缺失、锚点重复时不写入。
- Obsidian 打开和关闭时均能保存。
- 连续快速保存三条内容，均成功且顺序正确。
- 模拟目标文件在写入期间变化，不覆盖对方更新。
- 写入失败不损坏原文件，不遗留临时文件。

## 11. 当前不做

本轮检索未发现一个可直接复用、同时覆盖以下全部条件的开源项目：

- AutoHotkey v2。
- Windows 系统级快捷键。
- 不依赖 Obsidian 常驻。
- 直接安全写入指定 Markdown 锚点。
- 普通闪念、待办、新建笔记三种动作。
- 自动携带网页来源网址。
- 简单配置 UI。

### 12.3 开源复用规则

1. 优先使用 AutoHotkey v2 和 Windows 公共 API 自行实现最小功能。
2. 无明确许可证的 Gist 不直接复制或打包，只作为技术可行性证据。

5. 开源调研不会改变已确认的 `.ahk` 源码交付方式。

## 13. 风险与处理

### 13.1 网页来源并非所有场景都能取得

部分网页、浏览器扩展、桌面软件内嵌网页只提供纯文本，不提供 `SourceURL`。处理原则是“有可靠证据才写入”，不把当前浏览器网址强行归因给已经切换窗口后的剪贴板内容。

### 13.2 浏览器网址补取可能受浏览器状态影响

浏览器升级可能改变可访问性控件结构，导致 UI Automation 暂时失效；全屏网页、开发者工具、浏览器弹窗或快捷键拦截也可能使地址栏复制兜底失败。失败不阻止正文保存；若使用了地址栏复制兜底，必须恢复剪贴板。

### 13.3 多端同步并发

Android WebDAV、Obsidian 和同步盘可能同时修改目标笔记。程序通过修改前后校验和一次重试避免静默覆盖；仍冲突则让用户重按快捷键。

### 13.4 AHK 源码依赖运行环境

由于最终只交付 `.ahk`，运行电脑必须安装 AutoHotkey v2。启动时应检测主版本；检测到 v1 或未安装时，显示明确说明并退出。
